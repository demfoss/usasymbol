## 2. Принцип приоритизации

1. Сначала форматы, снимающие клик с уже имеющихся показов (PDF, квизы, игры).
2. Потом два ядровых запроса, застрявших на 5-й странице (флаги, столицы).
3. Только потом новые категории — и **сразу в комплекте с PDF и квизом**.
4. Новые страницы «просто фактов» не выпускаем: по текущим данным они приземляются на позицию 8–10 с нулевым CTR.

# ЧАСТЬ I. PDF-программа

## 3. Аудит существующей реализации

### Что уже есть и работает

`Controllers/PrintController.cs` (~400 строк) генерит PDF через QuestPDF (Community licence). Внутренний класс `SymbolListDocument` собирает A4-документ: заголовок, таблица с бирюзовой шапкой, футер со ссылкой на источник.

Резолвер `ResolveYamlPath` умный: ищет по `source` (`symbols`/`rankings`/`collections`), при промахе рекурсивно сканирует все каталоги. Поддерживает и `.yml`, и `.yaml`.

**Ключевой актив: 818 страниц уже имеют готовый блок `table:`** с `columns` и `rows` — то есть PDF для них собирается без единой правки контента:

| Раздел | С таблицей | Всего |
|---|---|---|
| `Content/symbols/` | 35 | 36 |
| `Content/rankings/` | 626 | 639 |
| `Content/collections/` | 157 | 285 |

### Почему этого не существует для Google

Восемь проблем, найденных в коде:

**1. PDF отдаётся только по POST с antiforgery-токеном.**
`Views/Shared/Pages/_PrintableWidget.cshtml` рендерит `<form method="post">` с `@Html.AntiForgeryToken()`. Краулер форму не отправит. Ссылочный вес никуда не течёт.

**2. GET-версия отдаёт не файл, а редирект.**
`[HttpGet("/print/download")]` → `ResolvePrintRequest(..., generatePdf: false)` → `RedirectPermanent(sourcePath)`. То есть даже прямая ссылка на PDF возвращает 301 на обычную страницу.

**3. Явный запрет индексации.**
`Response.Headers["X-Robots-Tag"] = "noindex, nofollow, noarchive"` — стоит до ветвления, применяется ко всем ответам.

**4. Картинки принудительно выключены.**
В конструкторе документа захардкожено `IncludeImages = false`, параметр метода `includeImages` до документа не доходит. `GetVisibleColumnIndices()` при этом **вырезает все колонки, у которых в ключе или заголовке есть «image»**.

Последствие: в `Content/symbols/flags.yml` первая колонка — `symbol_image: "Flag"` с путями `/images/flags/alabama/flag.webp`. **PDF «State Flags Chart» сейчас генерится вообще без флагов.** То же у birds, flowers, trees, seals.

**5. У PDF нет метаданных.**
`public DocumentMetadata GetMetadata() => DocumentMetadata.Default;` — ни Title, ни Author, ни Subject, ни Keywords. Google для PDF в выдаче берёт заголовок из метаданных документа; при их отсутствии показывает имя файла. Для indexable-PDF это критично.

**6. Логотип не выводится.**
`BuildHeader` проверяет `if (LogoBytes != null)`, но `LogoBytes` нигде не присваивается. Ветка мёртвая, брендинга в файле нет.

**7. Формат жёсткий.**
`PageSizes.A4`, `Margin(40)`, только portrait. Широкие таблицы (флаги: image + state + year + design + meaning) на портрете не помещаются. Нумерации страниц нет.

**8. Виджет стоит не везде.**
Рендерится только в `Views/Listings/Detail.cshtml:150` и `Views/Rankings/_RankingBody.cshtml:71`. **В коллекциях его нет** — а `states-with-animals-on-the-flag` это коллекция, и это лучшая страница сайта (67 кликов, 3.86% CTR).

### Вывод по аудиту

Движок готов на 80%. Нужно не писать генератор с нуля, а снять четыре запрета (POST, редирект, noindex, картинки), добавить метаданные и построить поверх индексируемый слой страниц.

## 4. Архитектура `/printables`

Прецедент в проекте уже есть: `/tools` с 12 инструментами (`Controllers/ToolsController.cs`), включая `/tools/state-capital-flashcards`. `/printables` строим по той же модели.

### 4.1. Маршруты

Новый `Controllers/PrintablesController.cs`:

| Маршрут | Что отдаёт | Индексация |
|---|---|---|
| `/printables` | хаб, сгруппированный по сценарию использования | index, follow |
| `/printables/{slug}` | лендинг: превью, варианты, инструкция, кнопки | index, follow |

Легаси `/print/download` оставляем как есть с `noindex` — он обслуживает виджет на существующих страницах.

### 4.2. Как избежать дублирования с исходной страницей

Риск: `/printables/state-nicknames` и `/symbols/nicknames` — почти близнецы, если лендинг просто повторит таблицу.

Правило: **лендинг не дублирует контент, он описывает файл.**

Что на лендинге:
- превью первой страницы PDF (PNG-рендер, `<img>`);
- что внутри: число строк, колонки, формат листа, число страниц;
- варианты скачивания: цветной / Ч-Б, с картинками / без, worksheet;
- инструкция по печати (A4/Letter, поля, двусторонняя);
- 1–2 абзаца по теме под запрос «printable … pdf»;
- ссылки: на страницу-источник, на квиз, на 3 смежных printable.

Чего на лендинге **нет**: полной таблицы. Она остаётся на странице-источнике, куда ведёт явная ссылка.

`<link rel="canonical">` — на себя: это отдельный ресурс с отдельным интентом.

### 4.3. Блок `printable:` в YAML

```yaml
printable:
  enabled: true
  slug: "state-nicknames"          # /printables/state-nicknames
  title: "Printable State Nicknames List"
  file_title: "50 State Nicknames — Printable List"   # → PDF metadata Title
  description: "All 50 state nicknames with adoption years. One page, print-ready."
  keywords: ["state nicknames pdf", "printable state nicknames list"]
  orientation: portrait            # portrait | landscape
  columns: [state, nickname, year_adopted]   # подмножество table.columns
  include_images: false
  worksheet:
    enabled: true
    blank_columns: [nickname]      # колонка обнуляется под заполнение
```

Поле `slug` отдельно от slug страницы: `/rankings/geography/states-capital-cities` → `/printables/states-and-capitals`, потому что печатают именно «states and capitals».

## 6. Перелинковка

### 6.1. Что сломано сейчас

Проверил кластер столиц. Три актива на одну тему существуют и **не связаны ничем**:

- `/rankings/geography/states-capital-cities` — 8581 показ, 3 клика, поз. 51;
- `/quizzes/state-capitals-quiz`;
- `/tools/state-capital-flashcards`.

Grep по `Views/` и по обоим YAML: единственная ссылка на флэшкарты во всём проекте — карточка в `Views/Tools/Index.cshtml:59`. Страница-рейтинг не знает ни про квиз, ни про флэшкарты. Квиз не знает про рейтинг.

То же самое будет с printable, если не заложить правило.

### 6.2. Правило треугольника

Каждая тема обязана иметь три формата, связанных в обе стороны:

```
        данные (ranking / listing / collection)
           /                              \
          /                                \
   printable  ←——————————————————————→  quiz / tool
```

Реализация — блок в YAML источника:

```yaml
formats:
  printable: "/printables/states-and-capitals"
  quiz: "/quizzes/state-capitals-quiz"
  tool: "/tools/state-capital-flashcards"
```

Рендерится единым партиалом `_FormatsStrip.cshtml` под H1 на всех трёх типах страниц. Это и навигация, и сигнал Google, что у темы есть глубина.

Темы, где треугольник собирается сразу из готового: столицы, аббревиатуры, флаги, птицы, девизы, прозвища, печати, номерные знаки, формы штатов.

### 6.3. Замена POST-кнопки на ссылку

`Views/Shared/Pages/_PrintableWidget.cshtml` сейчас — форма. Меняем на:

```html
<a href="/printables/@printableSlug" class="...">
  <i class="fa-solid fa-file-pdf"></i> Printable PDF
</a>
```

Для Tier B, где лендинга нет, — прямая ссылка на `/printables/{slug}.pdf`.

Это единственная правка, которая заставит ссылочный вес течь к новому разделу.

### 6.4. Подключить виджет к коллекциям

`Views/Collections/Detail.cshtml` — добавить `_PrintableWidget` рядом с тем местом, где он стоит в `_RankingBody.cshtml:71`. 157 коллекций с таблицами сейчас лишены печати, включая лучшую страницу сайта.

### 6.5. Автолинковка: механизм и найденный баг

В проекте есть автоматическая перелинковка — `Extensions/MarkdownExtensions.cs`, метод `RenderAutoLinks()`. Фразы для неё собираются в `ExtractPhrasesFromYaml` из трёх источников:

1. slug страницы (дефис → пробел);
2. `page.h1`;
3. блок `auto_link_phrases:` в YAML — ручной override.

Бюджеты: `MaxAutoLinksPerPage = 6`, `MaxAutoLinksPerParagraph = 2`, `MinCharsBetweenAutoLinks = 40`, владение фразой — first-writer-wins.

**Баг: `LoadYamlUrlTargets` перечисляет только `*.yml`:**

```csharp
Directory.EnumerateFiles(path, "*.yml", SearchOption.AllDirectories)
```

`Content/rankings/` содержит **141 файл с расширением `.yaml`** — они полностью исключены из автолинковки, на них не ведёт ни одной автоматической ссылки. Почти вся категория `agriculture` (133 файла) именно такая.

При этом спрос по ним есть: `what state produces the most chicken` (74 показа), `beef production by state` (45), `peanut production by state` (25), `grape production by state` (18), `barley production by state` (8), `top apple producing states in the us`, `lumber production by state`.

Фикс — одна строка, перечислять оба расширения. Это самая дешёвая правка во всём плане.

### 6.6. Куда направить автолинковку под наши цели

После фикса прописать `auto_link_phrases` так, чтобы вес шёл в пилларные страницы:

| Цель | Фразы |
|---|---|
| `/state-flags` | «state flags», «us state flags», «all 50 state flags», «state flag» |
| `/state-capitals` | «state capitals», «states and capitals», «us state capitals» |
| `/printables` | «printable list», «printable pdf» |

Учесть first-writer-wins: фразу «state flags» сейчас может держать любая из 38 коллекций флагов. Перед назначением проверить, кто владеет, и снять фразу у текущего владельца.

## 11. Краулинговый бюджет: раздел compare

### Что сделано правильно

`Helpers/SitemapBuilder.cs:421` — карта сайта для compare намеренно ограничена, и в коде это прокомментировано: 63 пары в обзоре, 25 Tier-One пар × 47 отобранных метрик, 17 хабов категорий. Итого **~1 600 URL**. Кто-то уже думал про краулинговый бюджет.

### Проблема

Ограничена **только карта сайта**. Маршруты обслуживают любую комбинацию:

```
/compare/{pair}/{metric}
```

Пар: 50×49/2 = **1 225**. Метрик в `ComparisonMetricsConfig`: **~200**. Потолок — **~245 000 URL**.

И они связаны ссылками: `Views/Compare/_MetricComparisonList.cshtml:56` рендерит `<a href="/compare/@Model.PairSlug/@result.Metric.Slug">` для **каждой** метрики на **любой** странице пары. То есть краулер попадает в комбинаторный лабиринт по обычным внутренним ссылкам, минуя карту сайта.

**Директивы `noindex` во всём проекте нет нигде, кроме `PrintController.cs:123`.** Grep по `Controllers/CompareController.cs`, `Views/Compare/*.cshtml` и `_Layout.cshtml` — пусто.

### Что говорят данные

Compare-страницы получают показы и почти не получают кликов:

| Запрос | Показы | Позиция |
|---|---|---|
| `oregon vs washington living` | 109 | 18.6 |
| `massachusetts vs texas` | 80 | 34.4 |
| `texas vs massachusetts` | 61 | 34.7 |
| `cost of living in alaska vs texas` | 57 | 11.0 |
| `delaware vs florida taxes` | 50 | 17.1 |
| `compare connecticut state tax with new york` | 37 | 25.9 |
| `maine vs vermont` | 31 | 29.2 |

Позиции 11–35, кликов около нуля. При этом потенциально сотни тысяч почти-дубликатов конкурируют за краулинговый бюджет с теми страницами, которые нам нужны в топе.

Это правдоподобное объяснение того, почему `state flags` — профильный запрос домена — сидит на позиции 46.

### Что делать

1. **Проставить `noindex, follow`** на compare-комбинации вне Tier-One. Логика уже написана — `BuildCompareUrlsAsync` знает, какие пары и метрики считаются индексируемыми. Вынести этот список в общий сервис и переиспользовать в `CompareController`.
2. **Проверить в GSC** отчёт «Индексирование страниц» → «Просканирована, но пока не проиндексирована» и «Обнаружена — не проиндексирована». Если там десятки тысяч compare-URL, диагноз подтверждён.
3. `rel="nofollow"` на ссылки метрик вне Tier-One в `_MetricComparisonList.cshtml` — как дополнительная мера, но `noindex` первичен.

Порядок важен: это надо сделать **до** запуска 800 новых PDF, иначе новые URL пойдут в ту же очередь.

## 12. Рендер-блокирующий CSS и протухшая сборка

`Views/Shared/_Layout.cshtml:108–113` подключает шесть таблиц стилей, все render-blocking:

| Файл | Размер |
|---|---|
| `main.css` | **176 KB** |
| `site.css` | **87 KB** |
| `page-data-hero.css` | 20 KB |
| `editorial-typography.css` | 16 KB |
| `symbol-detail.css` | 15 KB |
| `key-takeaways.css` | 7 KB |
| **Итого** | **~321 KB** |

Плюс Font Awesome с CDN.

### Две конкретные проблемы

**1. Загружаются и исходник, и результат сборки.**

`package.json`: `"build:css": "tailwindcss -i ./wwwroot/css/site.css -o ./wwwroot/css/main.css --minify"`.

То есть `site.css` — это **вход** Tailwind. Он начинается с:

```css
@tailwind base;
@tailwind components;
@tailwind utilities;
```

и дальше ~87 KB кастомных стилей. `main.css` — скомпилированный выход, содержащий все утилиты Tailwind **плюс те же самые кастомные стили**.

Браузер получает оба. Кастомный CSS едет дважды, а три директивы `@tailwind` отдаются как невалидный CSS. Экономия от простого удаления `site.css` из layout — **~87 KB на каждой загрузке**.

**2. Сборка протухла.**

`main.css` — 23 июля. `site.css` — 25 августа. Больше месяца правок в исходнике не пересобраны. Сейчас это не заметно только потому, что `site.css` грузится ещё и напрямую — то есть баг маскирует сам себя. Как только уберём дубль, часть стилей отвалится, если не пересобрать.

**Порядок:** сначала `npm run build:css`, проверить визуально, потом убрать `site.css` из layout.

### Почему это в плане про CTR

На сайте полный программатик-стек (см. раздел 13). LCP влияет и на позиции, и на viewability рекламы, то есть на RPM напрямую. 321 KB блокирующего CSS — это то, что бьёт по обеим метрикам сразу.

## 13. Монетизация меняет расчёт приоритетов

`wwwroot/ads.txt` — полный программатик-стек: manager domain `journeymv.com`, AdSense, Media.net, Index Exchange, TripleLift, Sharethrough, PubMatic, Rubicon и ещё около сорока SSP.

Из этого следует вещь, которая меняет обоснование всего плана:

**Доход пропорционален просмотрам страниц, а не кликам из поиска.**

Один клик на страницу факта — это одна сессия, один экран, один набор показов рекламы, и уход. Один клик на квиз — это 10 вопросов, несколько экранов, 5–10 наборов показов. Флэшкарты, игра на буквах, printable с превью и вариантами — то же самое.

То есть форматный сдвиг из раздела 2 оправдан дважды: квизы и игры не только собирают клик, который выдача не может перехватить, но и дают в разы больше рекламных показов на клик.

**Отсюда две поправки:**

1. В метрики добавить **страницы на сессию** и **сессии на пользователя** (GA4), а не только клики из GSC. Сейчас мы меряем только вход.
2. При выборе между «ещё одна страница фактов» и «квиз по уже имеющимся данным» — квиз выигрывает даже при равном числе кликов.

## 15a. Заголовок, который отдаёт ответ, убивает клик

Внутри одного кластера флагов есть почти чистый естественный эксперимент.

| Страница | Позиция | Показы | Клики | CTR |
|---|---|---|---|---|
| `collections/flags/states-with-animals-on-the-flag` | 6.38 | 1735 | **67** | **3.86%** |
| `collections/flags/states-with-birds-on-the-flag` | **2.27** | 1694 | 2 | **0.12%** |

Одна рубрика, один формат, одинаковый объём показов. Страница про птиц стоит **на четыре позиции выше** и собирает в 33 раза меньше кликов.

Разница видна в разметке:

```yaml
# states-with-birds-on-the-flag.yml
title: "10 US State Flags With Birds in One Complete List"
description: "10 US state flags feature birds: nine bald eagles and Louisiana's
  pelican. The complete list shows every flag, bird species, and location."

# states-with-animals-on-the-flag.yml
title: "State Flags with Animals | Bears, Birds & Bison"
description: "California's extinct grizzly, Wyoming's bison, Louisiana's pelican,
  and Oregon's reverse-side beaver show how animals appear on flags."
```

Первый вариант выдаёт исчерпывающий ответ прямо в сниппете: сколько (десять), какие (девять орлов и пеликан). Человек, искавший `which us state flags have birds on them`, узнал всё и не пошёл на сайт. Второй не называет числа и обещает разнообразие — приходится кликать.

По головному запросу: `state flags with animals` — 66 показов, 11 кликов, **16.67%**.

### Правило для редполитики

**В `seo.title` и `seo.description` не сообщать полный ответ на счётный или однофактовый запрос.** Отдавать категорию, диапазон и обещание деталей — число и перечисление оставлять на странице.

Это прямо противоречит нынешнему стилю «quick answer первым делом», который отлично работает внутри страницы и вредит в сниппете. Разделить: `quick_answer` — на странице, `description` — приманка.

### Что уже исправлено

Аудит по всему контенту: **110 файлов** имеют `seo.description`, открывающийся счётом («Nine state flags…», «Twenty-seven U.S. state flags…», «37 state flags…»).

### Очередь на потом

**Не тронуто, требует решения:**

- `rankings` — 47 файлов. Смотреть выборочно: править имеет смысл только те, что уже в топ-20, иначе CTR определяется позицией, а не сниппетом.

Это одна пара страниц, а не доказанный закон: часть разрыва может объясняться тем, что для запросов про птиц Google рисует AI Overview или картиночный блок. Поэтому не переписываем всё разом.

Проверка дешёвая: взять 10–15 страниц в топ-10 с CTR ниже 0.5%, переписать только `description`, замерить через 3–4 недели. Кандидаты видны сразу — все страницы `/states/*/borders` (34 472 показа, 51 клик, 0.15%) и `/states/*/flower` (2890 показов, **1 клик**, 0.03%).

Разбивка по разделам (из экспорта страниц; период отличается от свежего экспорта запросов, поэтому смотреть на пропорции, а не на абсолютные числа):

### Два вывода

**1. Коллекции — лучший формат на сайте, и он недоинвестирован.**

1.21% CTR против 0.18% у рейтингов и 0.50% у compare. По кликам на страницу — 5.2 против 2.1 и 0.3, то есть коллекция в **17 раз** эффективнее compare-страницы.

Логично: коллекция это и есть «список + превосходная степень», ровно тот формат, который по данным раздела 1 кликают.

При этом коллекций **285**, а в выборку попало 16 — и **13 из них про флаги**. То есть работает только один развитый кластер, остальные категории (`capitals`, `crime`, `culture`, `geography`, `laws`, `nature`, `sports`) не дотянуты.

**2. Compare занимает больше половины проиндексированных страниц выборки** (537 из ~1000) и даёт 0.3 клика на страницу. Это количественное подтверждение раздела 11.

## 18. Испанская версия — не делать

**Потерянное время, сейчас вредно.**

1. **Ядро не занято на английском.** `state flags` — 46, `state capitals` — 59. Пока профильные запросы на пятой странице, вторая языковая версия отнимает ресурс у нерешённой задачи.
2. **Масштаб дублирования.** ~5 500 страниц плюс генерируемые compare-URL. Испанский слой — x2 к объёму, hreflang на каждой, отдельные sitemap и мониторинг.
3. **Аудитория ищет на английском.** `states and capitals`, `state abbreviations quiz` — это домашка в американской школе, она на английском, включая испаноязычных школьников. В экспорте за месяц ноль испаноязычных запросов; единственный иноязычный — шведский `kaliforniskt motto` (379 показов, 0 кликов).
4. **Ценность в данных, не в тексте.** Сайт табличный. Перевод «Alabama → Northern Flicker → 1927» не добавляет ничего, а обвязку придётся переводить и поддерживать вручную при каждой правке.
5. **Проблема в CTR, а не в охвате.** 60 000 показов при 0.6%. Новый язык масштабирует показы — ровно ту метрику, которая и так раздута.

**Когда вернуться.** Одновременно: (а) `state flags`, `state capitals`, `state symbols` в топ-10 на английском; (б) в GSC появились испаноязычные запросы или трафик из Мексики / Испании / Латинской Америки.

**Что вместо.** Тот же ресурс в printables и квизы. `state fruits list` при 70 показах даёт 11 кликов — 15.7%. Это лучший показатель сайта, и получен он форматом, а не объёмом.
