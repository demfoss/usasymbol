# Деплой usasymbol.com

## 1. Код и контент (GitHub → Azure)

Пуш в `master` запускает `.github/workflows/deploy.yml`: сборка .NET 9 и деплой на Azure App Service `usasymbol`. Занимает ~5–10 минут.

```powershell
cd D:\проекты\usasymbol
git add -A
git commit -m "..."
git push origin master
```

Статус: GitHub → Actions → «Deploy to Azure App Service».

Картинки (`wwwroot/images`) в git не попадают (`.gitignore`) — их отдельно заливаем в Bunny (шаг 2).

## 2. Картинки (Bunny CDN)

Картинки отдаются с `https://usasymbol.b-cdn.net`. Загрузка в хранилище Bunny — встроенной командой приложения. Ключ хранилища лежит в user-secrets, поэтому нужен `Development`.

```powershell
cd D:\проекты\usasymbol\usasymbol
$env:ASPNETCORE_ENVIRONMENT = "Development"
$env:DOTNET_ROLL_FORWARD = "Major"
dotnet run --no-launch-profile -- --sync-bunny-images
```

- `ASPNETCORE_ENVIRONMENT=Development` — без него ошибка «Bunny:StorageApiKey is required».
- `DOTNET_ROLL_FORWARD=Major` — на этом компьютере стоит только .NET 10, проект собран под .NET 9. Если поставить .NET 9 Runtime — строка не нужна.

### Как синхронизация решает, что заливать

**Обычный запуск** (`--sync-bunny-images`):

- берёт список, сохранённый в Bunny после прошлого запуска (`.sync/usasymbol-images-v1.json`: размер + дата изменения каждого файла);
- файл с теми же размером и датой — пропускает без запросов к хранилищу;
- если файла нет в списке или размер/дата не совпали — один раз читает содержимое **только этой папки** в хранилище и сравнивает размер: такой же размер → пропуск, иначе → заливка;
- обычно проходит за секунды (по одному лёгкому запросу на папку с новыми/изменёнными файлами).

**С пересборкой списка** (`--sync-bunny-images --rebuild-bunny-image-manifest`):

- читает реальный список файлов в хранилище Bunny (несколько минут);
- файл с тем же размером считается уже загруженным (дата не важна);
- заливает только то, чего в хранилище нет или где другой размер;
- сохраняет новый правильный список.

### Если папку `wwwroot/images` скопировали / восстановили / перенесли

У всех файлов меняется дата. С 2026-10-02 обычный запуск это переживает: файлы с тем же размером, что в хранилище, не перезаливаются (будет по запросу на каждую папку — несколько минут вместо секунд). `--rebuild-bunny-image-manifest` для этого больше не обязателен.

История (2026-10-02): папка пересоздана в 01:23 → старая версия синхронизации перезаливала всё (3 000+ файлов за час). После правки: проверено 9 971, залито 38. Проверка: дата одного файла изменена → 1 запрос к его папке, залито 0.

### Прочее

- Список файлов сохраняется **только в конце** прогона. Если прервать синхронизацию — следующий запуск начнёт сначала.
- Долгий прогон запускать в отдельном окне PowerShell и не давать компьютеру уснуть (`powercfg /change standby-timeout-ac 0`).
- Синхронизация не сбрасывает кэш CDN. Новые файлы видны сразу; картинку, заменённую под тем же именем, CDN может отдавать старой до истечения кэша — тогда Purge в панели Bunny.
- Один файл может упасть с обрывом соединения — просто повторить запуск, он догрузится.
